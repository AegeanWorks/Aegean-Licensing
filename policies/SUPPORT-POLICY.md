# Support and Update Policy

**Version 1.0 — October 2026**
**Contact**: `aegean-licensing@proton.me`

This policy tells a user what support to expect. It is a statement of intent, not a warranty or an
SLA. A paid SLA, if any, must be written in an Order Form.

## Personal and free tiers (AL, AGL, ASL)

- **AS IS.** No support, maintenance, update or response-time commitment.
- **Security fixes.** AegeanWorks tries to fix a confirmed critical vulnerability in the current
  version, but does not promise a release date or a backport.
- **Questions.** Community documentation and the public issue tracker are the first stop. A reply
  is not guaranteed.
- **Modified builds.** AegeanWorks cannot support a fork, a modified build or a third-party
  integration; reproduce on an unmodified release first.

## Commercial tier (ACL-1.0)

Support is defined only by the Order Form. It may include:

- an initial response target;
- a supported version window;
- a security-fix commitment;
- an upgrade path and notice period; and
- a named technical contact.

Unless the Order Form says otherwise, ACL-1.0 includes **no** support, no SLA, no source escrow and
no obligation to release a new version within a particular period.

## Versions and end of life

1. Each release names its governing license and version.
2. A later version may change terms; a copy already granted keeps its grant.
3. AegeanWorks may declare a version end-of-life. It will publish the date and the last security
   release it intends to provide, subject to the Order Form.
4. A restricted version is not supported publicly; support terms, if any, are in a separate
   agreement.

## Security

Report a vulnerability under [SECURITY-DISCLOSURE.md](SECURITY-DISCLOSURE.md). Do not open a public
issue with exploit details. A security report is not a support ticket and does not create an SLA.

- Security: `security@aegeanworks.dev` (fallback: `aegean-licensing@proton.me`)
